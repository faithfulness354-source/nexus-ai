# NexusAI Roleplay — Project Instructions

## Overview
Full-stack AI roleplay chatbot platform inspired by Janitor AI. Dark-mode-first, purple accent (#7C3AED), no auth (single-user).

## Tech Stack
- App Router, Tailwind CSS, Prisma ORM, PostgreSQL
- LLM routing: OpenAI, Anthropic, Gemini, OpenRouter, Custom endpoints
- Character card format: Chub V2 JSON spec

## Database Tables
Character, ChatSession, Message, MeterState, ProviderConfig, GenerationSettings

## Key Routes
- `/` — Character gallery with search/filter/NSFW toggle
- `/characters/new` — Character editor (create)
- `/characters/[id]/edit` — Character editor (edit)
- `/characters/[id]/chat` — Main chat interface with streaming
- `/settings` — Provider API key configuration

## API Routes
- `/api/characters` (GET/POST), `/api/characters/[id]` (GET/PUT/DELETE)
- `/api/characters/[id]/export`, `/api/characters/import`
- `/api/sessions` (GET/POST), `/api/sessions/[id]` (GET/PUT/DELETE)
- `/api/sessions/[id]/branch`, `/api/sessions/[id]/messages`
- `/api/chat/stream` (POST — streaming)
- `/api/settings/providers` (GET/POST)
- `/api/models/[provider]` (GET)

## LLM Provider Rules (user-mandated)
- OpenAI is fully removed (no UI, no routing, no fallback, no DB row).
- Google Gemini is the default provider everywhere. Default model `gemini-flash-latest` (DEFAULT_MODEL in lib/types.ts); schema default matches.
- `lib/llm/resolve.ts` resolves provider/model/key per chat request, auto-loading the saved Gemini key from ProviderConfig.
- `lib/llm/gemini.ts` falls back through GEMINI_FALLBACK_MODELS on 404/429/5xx (Google retires versioned models like 2.0/2.5-flash for new users — prefer `-latest` aliases).
- User asked for `gemini-2.5-flash` as default (Oct 2026) but the saved key gets 404 "no longer available to new users" for it; kept `gemini-flash-latest` and told the user. `usableGeminiModel()` + RETIRED_GEMINI_MODELS in lib/types.ts map retired/saved values to DEFAULT_MODEL in resolve, settings API and chat view.
- OPENAI ProviderConfig row deleted. The enum value stays in the schema only because removing it needs a data-loss flag (no rows use it).
- Gemini is always active: providers POST forces isActive=true and the settings switch is locked; settings page syncs state from the POST response after saving.

## NSFW Age Gate & Access Policy (Oct 2026)

## Tier-Based Payload Routing (Oct 2026)
- lib/payload-router.ts `payloadPolicy(tier, isAdmin, requestedMaxTokens)`. PROTECT mode = FREE + PLUS (non-admin): max_tokens 120, last 2 turns, 350-token total cap (input ≤230 via packWithinBudget), no lore, PROMPT scripts, image triggers, meters/status tracking, or full persona (anchor only), baseline only + "one paragraph" directive. HIGH mode = PREMIUM/ULTIMATE/admins: max_tokens 512 default (user setting clamped 350–2048 when advancedGeneration), 8 turns raw + rolling summary (ChatSession.memorySummary / memorySummaryUpTo, folded in batches of 8 by updateRollingSummary in chat/stream, extractive fallback), full definition, lore, persona triggers, images (still gated by sceneImages).
- compressBaseline (<100 tokens: name, voice, scene); the whole system prompt is minified (whitespace collapsed); minifyRules prunes empty JSON fields and drops meters when status tracking is off.
- Response headers X-Payload-Mode / X-Payload-Input-Tokens / X-Payload-Max-Output. Gemini disables thinking when maxTokens ≤600 (non-pro models).
- Plus is in PROTECT mode, so its advertised lorebooks/custom prompts are not injected in chat; one-line change in PROTECT_TIERS if the user wants Plus moved to HIGH.

## Plan Context Caps & Continuity Engine (Oct 2026) — REPLACES "Tier-Based Payload Routing" (PROTECT/HIGH output modes are gone)
- TIERS.contextTokens: FREE 4_000, PLUS 16_000, PREMIUM 32_000, ULTIMATE 64_000 (admins use 64k). payloadPolicy(tier, isAdmin, modelWindow): contextCap = min(plan, model window); inputBudget = 95% of cap − 350. Mode label STANDARD (Free/Plus) / HIGH (Premium+/admin) is informational only.
- Every tier: max_tokens 350, prompt directive 250–350 tokens; user maxTokens slider is ignored (hint text under slider). Gemini pro models get thinkingBudget 128 added on top of the cap.
- assembleTierPayload: last 10 messages (5 user + 5 assistant) + the new user message, then packWithinBudget purges oldest when over budget. DB/UI history is never trimmed. Rolling summary ("Story so far (canon)") now runs for all tiers.
- compressSystemPrompt (≤500 tokens incl. CONTINUITY_GUARDRAILS): identity header, core identity (systemPrompt+personality, fluff/example dialogue stripped), extracted [SYSTEM_PROGRESSION_ENGINE] block (or default), Heat 0–5, other meters, status-screen line, customRules.rules. exampleDialogue is never sent.

## Plan Enforcement (Oct 2026)
- Routing queue lib/priority-queue.ts: laneFor(tier,isAdmin) → standard (Free) / fast (Plus) / priority (Premium) / top-priority (Ultimate+admin); acquireSlot with LLM_MAX_CONCURRENT (default 12), priority then FIFO; max wait 45/60/90/120s → 503 QUEUE_BUSY (user msg deleted, credit refunded). chat/stream releases slot on done/error/cancel; headers X-Queue-Lane, X-Queue-Wait-Ms. It orders requests under load, it does not make the model faster.

- GenerationPanel: Free = samplingHidden (sliders not rendered, "See plans"), Plus = samplingLocked (disabled + upgrade callout), Premium+ = full.
- Lorebook POST/PUT return 402 without customPrompts (Plus+); DELETE allowed; hub disables New/Save for Free.
- payloadPolicy: admins bypass plan context caps (model window only). VIP badge label "VIP Creator".

## Context Counter & Post-Script Safety (Oct 2026)
- Chat ContextBar mirrors the real request: system tokens from header X-Payload-System-Tokens (pre-send estimate = min(raw definition w/o exampleDialogue, 500)), history = last 10 messages only, window = X-Payload-Context-Cap. Old counter summed full definition + all messages (6,824 vs 3,260 actually sent).
- applyScripts skips scripts whose pattern matches empty strings when inserting text, and rejects any replacement that more than doubles the text. trimIncompleteTail (lib/hubs.ts) drops a dangling half-sentence before the assistant reply is saved (only if ≥50% remains). Meters still parse from the raw reply.
